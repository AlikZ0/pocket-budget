# Pocket Budget / Мой бюджет

Offline-first личный финансовый планировщик для телефона, полностью на React + TypeScript. Все данные сохраняются **только локально в IndexedDB**, без сервера, аккаунтов и синхронизации. Интерфейс поддерживает **русский, английский и армянский** (Settings → Language).


### Обновление 1.4.0 — светлая, тёмная и системная темы

В **Настройки → Оформление** доступны три варианта: **Светлая / Light / Բաց**, **Тёмная / Dark / Մուգ** и **Как на устройстве / Use device setting / Համակարգային**. Системная тема отслеживает `prefers-color-scheme` и меняется вслед за настройками iOS, Android, Windows или Linux, даже если приложение уже открыто. Палитра применяется к основным экранам, формам, карточкам долгов, диалогам, графику, нижней навигации и системным полям ввода. Языки RU/EN/HY сохранены.

Выбранный режим находится в `settings.theme` **только в IndexedDB**, входит в экспорт/импорт ZIP и автоматически восстанавливается на другом устройстве. При импорте или открытии базы старой версии без `theme` включается **системный режим**. Имя базы `pocket-budget-v1`, схема Dexie v3 и версия ZIP v2 не менялись, поэтому переустановка с сохранением **того же URL** не должна удалять существующие данные. Перед обновлением всё равно сделайте ZIP-копию. Для автоматической смены темы нужен браузер с поддержкой `light-dark()` (Safari/iOS 17.5+, современные Chrome и Firefox). Из-за загрузки настройки из IndexedDB при запуске кратковременно может показываться тема устройства до восстановления сохранённого выбора.

Новые тесты: `tests/theme.test.ts` для выбора темы и совместимости старых данных; `tests/browser/theme.spec.ts` для переключения, перезагрузки и смены системной темы на 320, 390, 768 и 1280 px.

## Запуск / Run

Требуется Node.js **20.19+** (рекомендуется Node.js 22 LTS) и npm.

```bash
npm install
npm run dev
# откройте http://localhost:5173
```

Продакшен-сборка:

```bash
npm run check
npm test
npm run build
npm run preview
```

Готовая статическая сборка появится в `dist/`. PWA service worker создаётся во время `npm run build` (`vite-plugin-pwa` + Workbox). Service worker в режиме `npm run dev` намеренно не активирован. Проверяйте офлайн-режим через `npm run preview` или production HTTPS.

### Ключевые файлы

- `src/lib/models.ts` — строго типизированные сущности.
- `src/lib/db.ts` — Dexie, миграция до схемы v3, атомарные погашения и платежи, редактирование повторений, удаление связей.
- `src/lib/dates.ts`, `src/lib/recurrence.ts` — календарные даты без UTC-сдвигов, 29/30/31 число, повторения.
- `src/lib/debts.ts` — баланс долгов по истории погашений.

- `src/lib/backup.ts` — ZIP, полная валидация и транзакционный импорт.
- `src/components/` — формы и UI.
- `src/lib/i18n.ts` — RU/EN/HY переводы.
- `src/lib/theme.ts` — выбор системной/явной темы и синхронизация цвета интерфейса браузера.
- `tests/` — Vitest, fake-indexeddb, реальный JSZip round-trip и rollback.

## Как использовать

1. При первом открытии можно сразу **восстановить ZIP-копию** с другого устройства или выбрать AMD, RUB, USD либо EUR и указать остаток на начало выбранного дня и дату начала учёта (не позже сегодняшней).
2. В «Операции» добавляйте уже произошедшие доходы или расходы. Для будущей зарплаты, ипотеки и регулярных платежей используйте «План».
3. Правила поддерживают разовые, еженедельные, ежемесячные и ежегодные повторения. Для платежей 29–31-го числа учитывается последний день короткого месяца; в следующих месяцах возвращается исходный день.
4. Нажмите значок действия у ожидаемого платежа, затем «Отметить выполненным». Вы сможете задать фактическую дату и сумму. В той же транзакции создаётся фактическая операция и помечается экземпляр расписания. Двойное списание исключено.
5. Для отдельного платежа доступны перенос даты, изменение суммы и отмена. Отменённые экземпляры (включая разовые) остаются в истории плана, но не влияют на прогноз. При редактировании повторяющегося платежа можно выбрать только этот экземпляр или его и последующие. Выполненные операции не удаляются при разделении правила.
6. «Обзор» показывает остаток долга (если долги есть), фактический остаток, прогноз на конец месяца и года, а также дни возможной нехватки денег. Просроченные расходы планируются на сегодня; просроченные доходы исключаются до изменения даты.
7. Откройте **План → Долги**, нажмите **Добавить долг**, укажите общий долг (например, 96 000 AMD), затем каждый месяц добавляйте погашения (например, по 10 000 AMD). В списке видны первоначальная сумма, уже выплаченная и остаток, а в истории — каждое погашение с датой **и остатком после этого погашения**. Кнопка «Весь остаток» подставляет сумму для окончательного закрытия долга. Каждое погашение автоматически создаёт фактический расход в «Операциях». При изменении или удалении погашения связанный расход изменяется/удаляется в той же транзакции. Сам долг не влияет на прогноз наличных до момента реального платежа.
8. В «Настройки → Оформление» можно выбрать светлую, тёмную или системную тему. Выбор сохраняется в базе и в ZIP. В «Настройки» можно создавать и переименовывать категории и объекты. При удалении выбирается другая категория/объект либо снятие привязки.

**Демонстрационные операции не создаются автоматически.** Их можно добавить кнопкой в настройках, только если операции и правила отсутствуют.

### Деньги и даты

Денежные значения хранятся как безопасные целые числа минимальных денежных единиц (копейки / центы / лума). AMD в этом проекте использует ISO 4217 minor unit = 2. Внутренняя арифметика целочисленная; форматирование отображения — `Intl.NumberFormat`. В каждой базе одна валюта. Конвертации нет. Даты хранятся строками `YYYY-MM-DD`, календарные вычисления используют UTC-конструкторы и не зависят от часового пояса устройства.

### ZIP-перенос / ZIP transfer

1. На старом телефоне: **Настройки → Экспортировать данные**. Сохраните файл `budget-backup-YYYY-MM-DD.zip` в «Файлы» или передайте его через AirDrop, мессенджер, кабель и т. п.
2. На новом телефоне откройте приложение и выберите **Настройки → Импортировать данные** (если это чистая установка, нажмите «Восстановить из ZIP» на первом экране — предварительная настройка не нужна).
3. Приложение проверит CRC32, содержимое двух файлов, версию формата, все ID, даты, суммы, существование ссылок и соответствие выполненных платежей фактическим операциям. Вы увидите валюту, дату экспорта, количество операций, правил плана и долгов.
4. Нажмите **Скачать копию текущих данных**, если хотите сохранить содержимое нового устройства. Затем подтвердите полную замену данных. Загрузка выполняется одной транзакцией IndexedDB: ошибка не оставляет частичного импорта.

ZIP содержит `manifest.json` (версия формата, приложения, время экспорта) и `data.json` (settings, categories, objects, transactions, rules, overrides, debts, debtPayments). **Формат версии 2**; импорт резервных копий версии 1 поддерживается. Старая база IndexedDB автоматически обновляется до схемы версии 3 без удаления существующих операций. В разделе «Настройки» есть отдельная проверка целостности данных, которая проверяет суммы и связи без изменения базы. Архив *не зашифрован*: не передавайте его посторонним. Экспорт не удаляет исходные записи. **Данные не синхронизируются автоматически.** Очистка данных сайта/браузера или удаление PWA может удалить IndexedDB; экспортируйте резервные копии регулярно.

### Размещение статического сайта / Static hosting

Опубликуйте **содержимое** `dist/` на HTTPS-хостинге (GitHub Pages, Netlify, Cloudflare Pages, Nginx). Серверный API не нужен. Vite настроен на относительные пути `base: './'`. Для маршрутов используется собственное состояние без history-route, поэтому rewrite-правила для SPA не нужны. HTTPS обязателен для service worker на чужих устройствах; исключение — localhost.

Для локального теста с другого телефона в той же Wi‑Fi сети: `npm run dev -- --host 0.0.0.0`, открыв IP ноутбука. Но **на обычном HTTP по LAN service worker не установится**. Для установки PWA на телефон разместите `dist/` на HTTPS или используйте локальный HTTPS сертификат, которому доверяет телефон.

- iPhone: открыть HTTPS-сайт через Safari → Share → Add to Home Screen / «На экран Домой».
- Android: открыть HTTPS-сайт в Chrome → Install app / «Установить приложение».

После первой полной загрузки PWA будет доступна офлайн. Данные устройства сохраняются в его IndexedDB. Не используйте приватный/инкогнито-режим для долговременных записей.

## English quick start

1. Run `npm install && npm run dev` (or `npm run build` for static HTTPS hosting).
2. Choose currency, opening balance, and ledger start date. Record **completed** transactions under Transactions and **future** items under Plan.
3. Under Plan → Debts you can create a liability and record partial repayments. Each repayment adds a linked cash expense, and the entire history is available for editing and backup. Use a plan occurrence's actions to complete, move, adjust, or cancel it. A completed occurrence creates a linked actual transaction exactly once.
4. Settings → Appearance → Light / Dark / Use device setting controls the theme and follows device changes in system mode. Settings → Language → English / Հայերեն switches the entire interface. Settings → Export / Import transfers **all** data manually using a ZIP archive. Import warns that current data will be overwritten.
5. For an installable, offline app, deploy `dist/` over HTTPS and add it to your phone's home screen.

## Тесты

`npm run test:core` запускает автономные проверки без зависимостей (если TypeScript уже установлен глобально). `npm test` запускает проверки: фактический баланс, дневная нехватка, просроченные доходы/расходы, отсутствие двойного списания, перенос даты в коротких месяцах, ZIP round-trip, отклонение повреждённых связей и атомарный откат IndexedDB при принудительной ошибке записи.

### Ограничения

- Это локальный планировщик, а не банковский счёт: реальный остаток нужно вводить и сверять самостоятельно.
- Горизонт прогноза ограничен допустимыми датами; в списке плана показываются повторения до конца второго следующего года. Далёкие повторения по-прежнему живут в правилах и будут рассчитаны при приближении периода.
- При изменении правила «этот и последующие» ранее выполненные платежи сохраняются в истории операций. Неисполненные индивидуальные настройки следующих экземпляров могут быть сброшены при изменении календарного графика; интерфейс запрашивает подтверждение.
- В финансовом планировщике нет импорта CSV, банковской синхронизации и автоматической конвертации валют.

### Проверка размеров экрана / Responsive browser checks

```bash
npx playwright install chromium
npm run test:e2e
```

Playwright открывает приложение в Chromium на ширинах **320, 390, 768 и 1280 px**, проверяет отсутствие горизонтального переполнения, переход на экран операций и открытие формы. Снимки сохраняются в `test-results/`. Это отдельная команда; `npm test` запускает быстрые тесты бизнес-логики.

### Исправление Safari / HTTP и миграция

Начиная с версии **1.1.0** устранено падение `crypto.randomUUID is not a function` на iPhone при запуске через `http://192.168.x.x`. Генерация ID использует `crypto.getRandomValues`, доступную и в обычном HTTP-контексте, с резервным путём для старых WebView. Для обновления просто разверните новые исходники или новую сборку **по тому же URL**: IndexedDB с прежним именем `pocket-budget-v1` и все существующие записи сохраняются, Dexie применяет миграцию схемы v3. Сначала скачайте ZIP-резервную копию прежних данных, если старая версия позволяет это сделать.

Разработка по HTTP/IP возможна, но iPhone не сможет установить service worker по обычному адресу локальной сети. Для офлайн-PWA нужен HTTPS. На телефоне после обновления страницы может понадобиться перезагрузить вкладку, чтобы сменить закешированные ресурсы.

## Изменения 1.2.0 / Quality pass

- **Без потери истории:** после изменения серии «этот и последующие» выполненные экземпляры старого расписания остаются доступны в плане и операциях. Перенесённый на более раннюю дату экземпляр попадает в правильный период.
- **Более строгая запись:** добавление/редактирование фактических операций проверяется внутри транзакции Dexie (дата, тип, денежная сумма, категория и объект). Действия над планом повторно проверяют актуальное состояние правила, поэтому устаревшая форма не выполнит уже изменённый или отменённый платёж.
- **Обзор:** чистое изменение денег за месяц и распределение фактических расходов по категориям. Суммы в денежных расчётах остаются целыми; процентные полосы отображения не влияют на расчёты.
- **Мобильный интерфейс:** окна удерживают фокус, закрываются по Escape, возвращают фокус после закрытия; сообщения больше не закрывают нижние поля формы. У полей есть программные метки, ошибки объявляются экранным читалкам. Ввод не вызывает автоматический масштаб Safari (`font-size:16px`). Учитываются safe-area и уменьшенная анимация.
- **Большие планы:** список запланированных экземпляров подгружает записи частями по 40, вместо попытки сразу отрисовать тысячи карточек.
- **Честный офлайн-статус:** приложение показывает состояние сети и предупреждает о недоступности PWA по HTTP-IP. Изменение HTTP → HTTPS *или другого домена/IP* означает другой origin и **другую IndexedDB**. До изменения адреса скачайте ZIP, затем импортируйте его на новом адресе. Из одного и того же браузера между адресами данные не перемещаются сами.
- **Проверка базовой логики без npm:** `npm run test:core` использует установленный системный TypeScript-компилятор и Node.js; выполняет 10 проверок календаря, дат, расчётов, истории и долгов. Для полного набора тестов нужна установка зависимостей (`npm install && npm test && npm run test:e2e`).

### Ограничение безопасности и синхронизации долгов

Запись долга в «План → Долги» отслеживает сумму обязательства, а история погашений создаёт реальные расходы. Однако отдельное повторяющееся правило расходов пока *не связано автоматически* с долгом: при ручном погашении долга не отмечайте такую же операцию второй раз. Это ограничение явно сохраняется в версии 1.2.0.

## Надёжность и точность / Quality notes

- При открытии приложения в полночь дата автоматически обновляется, включая прогнозы и просрочки. При возврате к вкладке после сна телефона дата синхронизируется повторно.
- Изменение расписания не разрешается, если среди будущих экземпляров уже есть выполненный платёж: это защищает от повторного списания по изменённой серии. Изменять остальные невыполненные даты можно отдельно.
- Выплаты долга хранятся отдельно от графика расходов, но каждая выплата связана с одной реальной операцией. Не дублируйте её второй операцией вручную.
- Проверка данных в настройках не меняет IndexedDB и не заменяет ZIP-бэкап.
- CI-тесты, реальные браузерные тесты и сборка требуют установки npm-зависимостей. Если регистр недоступен, можно прогнать независимые smoke-тесты через `npm run test:core` (с глобальным TypeScript).

Начальный остаток можно исправить в разделе **Настройки → Начальный остаток → Изменить**. После подтверждения изменится весь исторический и будущий баланс; операции не редактируются. Дата начала и валюта при этом остаются неизменными.

## Визуальные исправления 1.3.3

В разделе «Операции» и на вкладке платежей раздела «План» фильтры больше не скрываются в горизонтальной прокручиваемой строке. Вместо этого используются четыре подписанных поля: тип, категория, объект, месяц. На ширинах до 360 px они располагаются друг под другом; от 361 до 1080 px — в два столбца; выше — в четыре. Сброс доступен отдельной кнопкой. Вкладки статусов на телефоне тоже не требуют горизонтальной прокрутки.

На узких экранах записи показывают название и метаданные сверху, а сумму и действия — в отдельном нижнем ряду. Поля суммы и даты внутри мобильных форм располагаются вертикально, чтобы не обрезать дату и локализованные подписи. Исправлен постоянный пустой отступ для полосы прокрутки.

Добавлен Playwright-тест `tests/browser/filter-visibility.spec.ts`, который проверяет **видимость каждого фильтра** (а не только отсутствие горизонтальной прокрутки страницы), вкладок плана и сетку для RU / EN / HY на 320, 390, 768 и 1280 px.

База данных, формат ZIP и пользовательские записи не изменялись. Перед заменой файлов рекомендуется экспортировать резервную копию.
