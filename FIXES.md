# Исправления версии 1.3.1 — 31 октября 2026

Исправлены проблемы, найденные в реальном выводе `npm install`, `npm run check`, `npm test` и `npm run build` для версии 1.3.0.

## 1. TS2554: Dexie.transaction

Причина: TypeScript-перегрузка `Dexie.transaction()` не допускает восемь таблиц отдельными аргументами. Исправлены три вызова в `src/lib/db.ts`: чтение снимка, атомарная замена всех таблиц и начальная настройка. Передаём **массив таблиц** и последним аргументом callback. Dexie поддерживает такую форму; транзакционность экспорта/импорта сохранена. В `tables()` убрана аннотация readonly (`as const`), чтобы получить массив, совместимый с типами Dexie.

## 2. Playwright Test did not expect test() to be called here

Причина: Vitest 4 по умолчанию собирал файлы `tests/browser/*.spec.ts`, предназначенные для отдельного запуска Playwright. В `vite.config.ts` настроено `test.include: ['tests/*.test.ts']` и исключение браузерных тестов.

- `npm test` запускает Vitest (логика и IndexedDB).
- `npm run test:e2e` запускает Playwright (браузерные проверки).
- Для первого запуска e2e: `npx playwright install chromium`.

## 3. DatabaseClosedError в трёх тестах

Причина: тесты используют общую импортированную `db`. После `db.close()` и `db.delete()` Dexie 4 оставляет экземпляр закрытым; следующие тесты раньше пытались работать с ним без открытия. Теперь в `tests/backup.test.ts` и `tests/quality.test.ts` есть `beforeEach(async () => { await db.open(); })`. Независимые временные базы продолжают удаляться после тестов.

## 4. Проверка после патча

В этой среде выполнено `npm run test:core`: **11/11 успешных автономных проверок**. TypeScript-синтаксис исходников проверен отдельно. Полные `npm run check`, `npm test`, `npm run build` и `npm run test:e2e` здесь подтвердить нельзя: окружение не смогло получить npm-зависимости из реестра. Проверьте эти команды на своём компьютере и при необходимости пришлите новый вывод.

**Предупреждение о безопасности:** `npm install` сообщил о 10 уязвимостях и устаревшем `glob`. Это отдельный вопрос от ошибок сборки. Сначала получите точный отчёт командами `npm audit` и `npm audit --omit=dev`; не запускайте `npm audit fix --force` без проверки изменений мажорных версий.

## Обновление без потери бюджета

1. Если сайт уже используется, сначала экспортируйте ZIP-бэкап из настроек приложения.
2. Распакуйте этот архив в папку проекта с заменой файлов исходников. Не удаляйте данные браузера и не меняйте адрес опубликованного сайта без отдельного ZIP-переноса.
3. Выполните последовательно:

```bash
npm install
npm run check
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

Формат ZIP-резервных копий **не менялся** (версия 2). Схема IndexedDB и имя базы `pocket-budget-v1` не менялись. Исправление не требует миграции существующих данных.
