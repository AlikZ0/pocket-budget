# Визуальный аудит — 1.3.3

## Выявленная причина

Фильтры имели `display:flex`, `overflow-x:auto` и ограниченную ширину `max-width:145px`. На телефоне последний select оказывался за правой границей видимой области. Простая проверка `document.scrollWidth` этого не выявляла: горизонтальная прокрутка была *внутренней*.

## Исправления

- Четыре фильтра — сетка с шириной 100%, без внутреннего скролла, с видимыми метками.
- Один столбец на ширине до 360 px, два на 361–1080 px, четыре на широком экране.
- Кнопка сброса вынесена из набора фильтров, состояние `disabled` корректно отражает отсутствие активных фильтров.
- Вкладки плана на мобильном экране — две строки по два пункта, без внутренних прокручиваемых рядов.
- Карточки операций на телефоне: сумма и действия размещены отдельным нижним рядом, длинные названия переносятся.
- Формы на узком экране: сумма и дата идут друг под другом, увеличена доступная ширина.
- На 320 px дата скрывается из верхнего заголовка, валюта и название приложения остаются видимыми.
- Не резервируется постоянная пустая полоса `scrollbar-gutter:stable`.

## Что фактически проверено

- Chromium со стилями и DOM-структурой исправленного интерфейса: 320 / 390 / 768 / 1280 px × русский / английский / армянский (12 комбинаций): все 4 фильтра и все проверяемые элементы внутри viewport; `scrollWidth <= clientWidth`.
- Исходник TypeScript проверяется отдельным синтаксическим анализом.
- Тест полного приложения `tests/browser/filter-visibility.spec.ts` добавлен, но должен запускаться после `npm install` на машине разработчика.

**Ограничение:** автоматический визуальный тест выполнялся на статической странице с настоящим CSS проекта и эквивалентной HTML-структурой. Это не полноценный запуск React-приложения. Не утверждается, что проект прошёл production-сборку или тестирование в Safari на физическом iPhone.
